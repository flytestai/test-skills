# Market Screenshot Compare

对比两张展示同一行情列表、报价页面或金融界面的截图，并输出简洁的差异结论。

## 核心目标

1. 不漏掉共享可见字段。
2. 不把纯样式差异误报为字段差异。
3. 默认每次都完整输出当前截图识别到的 bug，不自动吞掉之前报过的问题。
4. 在需要高可靠识别时优先使用 skill 内置 OCR 自举运行时，降低漏检风险。
5. 自动区分盘中与盘后，按不同严格度处理差异。
6. 支持不同软件截图之间只比较共享字段，忽略排版与样式。

## 工作流

1. 仔细读取两张截图。
2. 检查表头或页面结构是否一致。
3. 按以下顺序对齐相同行：
   - 代码
   - 名称
   - 当代码和名称都稳定可见时，使用稳定的行位置
4. 先枚举两张截图里所有共享可见、且有明确字段名的字段。
5. 对共享字段逐个穷举比对，不能因为周边字段相似就跳过某个字段。
6. 默认忽略背景颜色、主题皮肤、纯样式差异和非字段类展示差异。
7. 将差异分成两类：
   - 可能因为页面刷新而变化的实时字段
   - 应该稳定，或应遵循统一计算口径的可疑字段
8. 默认忽略右下角截图时间，除非用户明确要求比较截图时间。
9. 如果当前差异和之前报过的问题类型相同，先向用户确认是否需要重复报；只有用户明确说“不需要重复报”时，才允许按问题类型去重。
10. 按用户要求的格式输出结果：
   - 完整差异报告
   - 不一致汇总
   - 疑似问题清单
   - 仅输出问题标题

## 盘中 / 盘后模式

默认自动识别截图时间，并判断为盘中模式或盘后模式。

### 时间判断原则

1. 优先使用截图内 OCR 识别到的业务时间或页面时间。
2. 如果截图内时间无法可靠识别，可退回参考图片文件时间。
3. 先识别截图所属市场，优先判断为 A 股或港股。
4. A 股盘中时段固定为交易日：
   - `09:30 - 11:30`
   - `13:00 - 15:00`
5. 港股盘中时段固定为交易日：
   - `09:00 - 12:00`
   - `13:00 - 16:00`
6. 其他时间一律按盘后处理。
7. 如果无法可靠识别出是 A 股还是港股，默认按盘后处理，避免把非交易时段误判成盘中。

### 盘后模式规则

- 对所有共享字段按严格一致处理。
- 只要同字段值不同，就应视为差异。
- 盘后不再用“截图时间先后”解释字段差异。

### 盘中模式规则

- 允许实时字段存在轻微差异，并优先判断是否可能由截图时间差导致。
- 如果属于以下实时字段，且差异很小，可不计为问题：
  - 最新
  - 涨跌
  - 涨幅
  - 均价
  - 涨速
  - 振幅
  - 总手
  - 金额
  - 换手
  - 量比
- 如果属于以下稳定或半稳定字段，即使盘中也要更严格：
  - 今开
  - 最高
  - 最低
  - 昨收
  - 总股本
  - 流通股本
  - 总市值
  - 流通市值
  - 市盈率
  - 市净率
- 若一边有值、另一边无值，不论盘中还是盘后，都应直接视为问题。

## OCR 增强模式

当需要高可靠字段识别时，优先采用 skill 内置的 PaddleOCR 自举流程：

1. 若当前 skill 目录下尚未准备本地 OCR 运行时，先自动创建本地虚拟环境并安装 PaddleOCR 依赖。
2. 对截图做预处理：
   - 放大
   - 灰度化
   - 提升对比度
   - 需要时做轻量锐化或二值化
3. 使用 OCR 提取整张图的文本框、文本内容和坐标。
4. 按字段名锚定结构化区域，优先识别以下高风险字段：
   - 今开
   - 最高
   - 最低
   - 昨收
   - 均价
   - 涨速
   - 振幅
   - 流值
   - 市值
   - 总股本
   - 总市值
   - 排名字段
   - 百分比字段
   - `--`、`nan`、`0.00%` 等占位值
5. 将 OCR 结果映射为“字段名 -> 字段值”的结构化结果。
6. 仅对两张截图的共享字段做差异对比。
7. 若 OCR 对某字段仍无法可靠识别，必须明确披露该字段“未能确认”，不能静默跳过。
8. 即使使用 OCR，也仍然要忽略背景色、主题、纯样式差异和右下角系统时间。

首次运行需要联网下载 Python 依赖包和 PaddleOCR 模型文件，但不要求使用者手动执行额外安装命令。

如果 OCR 自举失败，则退回到普通截图阅读模式，但仍必须执行共享字段穷举检查与未确认字段披露。

参考辅助脚本：

```text
scripts/compare_with_paddleocr.py
scripts/build_offline_bundle.py
```

## 对比规则

- 优先使用截图中的原始字段名。
- 将代码和名称作为行对齐的主锚点。
- 只比较两张截图中共享可见、且有明确字段名的字段；但只要属于共享字段，就必须检查，不能跳过。
- 在给出结论前，必须先形成一份“共享字段检查清单”，并逐项确认。
- 如果某个字段看不清、无法可靠识别，必须明确说明“该字段未能确认”，不能默默跳过。
- 对以下高风险漏检字段要重点检查，包括但不限于：
  - 今开
  - 最高
  - 最低
  - 昨收
  - 均价
  - 涨速
  - 振幅
  - 流股本
  - 流值
  - 总股本
  - 总市值
  - 排名字段
  - 百分比字段
  - `--`、`nan`、`0.00%` 这类占位值
- 默认忽略背景颜色、黑白主题切换、皮肤变化、图表配色变化，以及其他纯视觉风格差异；除非用户明确要求比较样式。
- 默认忽略右下角系统时间和任务栏时间，除非用户明确要求比较时间。
- 默认每次都要输出当前截图里识别出的全部问题类型，即使和之前相同也不能自动省略。
- 如果用户明确确认“相同 bug 不用重复报”，才允许启用去重。
- 去重时优先按“问题类型”而不是按“具体值”进行。即使数值不同，只要属于同一字段族或同一种展示模式问题，也视为同一类旧 bug。
- 例如以下类型在用户明确允许去重后，可以视为同类旧 bug：
  - 数量标识不一致
  - 排名统计不一致
  - 流值 / 总股本 / 总市值不一致
  - 空值样式不一致，如 `nan` 与 `--`
  - 脏数据、空白记录、异常列表项展示
- 只有在用户明确要求不重复报相同 bug 时，才只输出当前截图中新出现的问题类型。
- 行数不一致需要单独指出。
- 空白行、半截数据行、脏记录需要单独指出。
- 如果截图中包含业务时间戳，可以在判断差异是否异常前说明，但不要把右下角系统时间当作有效差异。
- 不要把明显属于实时刷新波动的字段轻易判为 bug。
- 对于以下字段，如果不一致，应更倾向于视为可疑问题：
  - 股本
  - 市值
  - 总市值
  - 应该共享统一计算公式的派生指标
- 如果一边是数值，另一边是 `--`、空白或明显异常占位值，应更倾向于视为展示或逻辑问题。
- 如果两张截图来自不同软件，仍只比较双方共享字段，不因为字段排序、排版、颜色、字号或面板布局不同而误报。

## 第三方软件对比

当两张截图明显不是来自同一个软件时：

1. 先忽略布局、样式、主题、背景色、字号、字段顺序差异。
2. 仅提取两边都明确可见、且字段名语义一致的共享字段。
3. 使用字段名语义对齐，而不是要求字段必须出现在相同位置。
4. 对共享字段逐个比对其行情值或其他数据值。
5. 某字段只在一边存在、另一边没有对应字段名时，不强行报错；因为这属于产品差异，除非用户明确要求比较字段覆盖率。
6. 某字段在两边都存在，但一边有值、一边无值，则必须报问题。

## 输出模式

根据用户要求，使用尽量轻量的输出格式。

### 当用户要求完整分析

- 按证券或对象列出不一致字段
- 说明这些差异更像正常波动还是可疑问题
- 将相似问题归类整理
- 明确说明“共享可见字段是否已全部检查完成”
- 若存在未能确认的字段，单独列出

### 当用户要求问题候选项

- 按问题类型汇总，而不是重复列出每一个代码
- 每条尽量简短
- 只保留有代表性的示例
- 默认仍要输出旧 bug 在本次截图中的再次出现
- 只有用户明确要求不重复报时，才抑制重复问题类型、只输出新增问题候选项

### 当用户要求只输出标题

- 输出简洁的一行式标题
- 当多个字段属于同一方向的不一致时，合并成一条标题
- 除非用户明确要求 bug 表述，否则不要主动写“BUG”
- 如果用户明确启用了去重，且去重后没有新增问题类型，应明确说明：排除已知问题后，当前截图未发现新的不一致项
- 只有在“共享字段已全部检查”或“未确认字段已明确披露”的情况下，才允许下“未发现新差异”的结论

## 压缩规则

- 当多个字段以相同方式不一致时，可合并为一个标题，例如：同一证券多个行情字段显示不一致。
- 行数不一致与脏数据展示问题，默认单独保留，除非用户要求更短的合并版本。
- 当用户要求发给开发或测试时，优先输出简短、直接的中文标题，不加多余解释。

## 默认风格

- 使用简体中文回复。
- 面向开发与测试，保持简洁直接。
- 先给结论，再补充必要说明。
