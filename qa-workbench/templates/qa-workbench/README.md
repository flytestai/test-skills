# QDesk · 本地测试工作台

一个只在本机运行的测试工作台，通过禅道 CLI 同步账号相关的 Bug、任务与项目数据，并提供日报、筛选、排序和本地快照能力。

- 前端：原生 HTML / CSS / JavaScript，无构建步骤。
- 后端：Node.js 原生 HTTP 服务，无第三方运行时依赖。
- 数据来源：本机 `zentao` CLI。
- 连接配置：只需 **ZenTao URL、账号、密码、显示姓名**，不需要产品 ID 或任务项目 ID。
- 数据范围：账号可访问的全部产品、项目与执行；Bug 取「我提交的 + 指派给我 + 我处理过的 AI 客服 Bug」，任务取可访问执行下的全部任务。
- 发版管理：导航位于任务管理上方，版本从任务的执行名称与 Bug 影响版本自动汇总；可设置每个版本的测试开始 / 结束时间、置顶版本、设置 P1 / P2 / P3 优先级并手动关闭发版。工作台只展示已设置测试时间的版本，测试时间、置顶、优先级与关闭状态均为本机独立记录。
- 打开体验：优先读取本地快照，禅道同步在后台静默执行。
- 默认只监听 `127.0.0.1`。

## 安全边界

- 禅道已有任务只读；本地任务可在 QDesk 创建、编辑、完成和删除。Bug 写操作只允许针对 `assignedTo` 为当前账号的记录。
- 我提交但已指派给他人的 Bug 不能修改；已关闭 Bug 的 `assignedTo` 会变成 `closed`，归属必须在关闭前确认。
- 批量关闭前必须先只读生成清单并让用户确认，只关闭清单内的 ID；默认超过 100 条会拦截。
- 每次写入后逐条复核状态和指派人，分别报告成功、失败、跳过项。

## 环境要求

1. Node.js 18 或更高版本。
2. 已安装并可使用禅道 CLI：`zentao --version`。
3. 任意一种凭证：
   - 本机禅道 CLI 已登录；或
   - 在工作台「配置禅道连接」中填写 URL、账号和密码。

## 快速开始

```bash
# 1. 生成配置（如果通过技能安装，安装器已自动完成）
cp config.example.json config.json

# 2. 启动服务
npm start
```

Windows 也可以双击 `start.bat`；macOS / Linux / Git Bash 可执行 `./start.sh`。

打开 **http://127.0.0.1:4173**，在「偏好与数据 → 配置禅道连接」中填写：

- 禅道 URL
- 登录账号
- 密码
- 显示姓名（可选）

点「测试连接」可先验证账号，并查看可访问的产品数与项目数；点「保存并同步」后开始后台同步。首次同步会遍历账号可访问的全部产品与执行，数据量大时可能需要几十秒；完成后页面自动更新，无需刷新。

如果只使用本机 CLI Profile，请把 `config.json` 中的 `tester.account` 设为 CLI 登录账号，或设置环境变量 `ZENTAO_ACCOUNT`。

## 功能

### QDesk 工作台

- 今日聚焦、质量雷达、最近动态和本周测试节奏。
- 「当日进度」综合进度环：只统计当天我名下待验证 Bug 和待完成任务；待发版版本与版本就绪度单独展示，不计入综合百分比。
- 待验证 Bug 包含指派给我、以及由我提交后需要我确认的 Bug；autojob 新建并指派给我的 Bug 也计入。
- 待发版数量只统计已设置测试结束时间、且尚未结束的版本；只设置开始时间、未设置结束时间的版本仍参与版本就绪度，但不计入待发版数量。测试结束时间已过的版本仍保留在发版管理并标记「已结束」，但不再计入待发版数量。未排期版本同样不计入待发版数量，已关闭版本不计入。
- 四张指标卡：今日待验证、我提交的未关闭 Bug、今日到期、待办任务。今日待验证列出我名下全部未验证 Bug（不限新增日期），点击单条直接打开对应 Bug 详情。
- 指标卡支持键盘 Enter / 空格操作。
- **客服反馈**：自动识别 `autojob` 等 AI 客服账号指派给我、或由我解决 / 关闭的 Bug，包括待验证、我已解决、已关闭和 P0/P1 未关闭。autojob 新建并指派给我的 Bug 计入待验证；由我解决后指派回客服的 Bug 显示为「我已解决」，不计入待验证。页面通过「客服反馈」筛选和下方「客服反馈跟进」面板跟进，不再单独显示顶部横幅。
- 客服反馈同步写入通知铃铛和当天工作日报。

### 发版管理

- 导航位于「任务管理」上方，版本列表来自禅道同步的任务执行名称与 Bug 影响版本。
- 自动汇总每个版本的任务总数 / 完成数 / 进度、待验证 Bug 与未关闭 Bug。
- 点击版本卡片中的「待验证 Bug」「未关闭 Bug」数量，直接跳到 Bug 跟踪并自动按该版本和对应口径筛选；版本筛选条固定在 Bug 列表顶部，滚动时保持可见，可一键清除。
- 可为每个版本设置 **测试开始时间** 与 **测试结束时间**，状态自动标记为测试中、待开始、已结束、未排期或已关闭。
- 每个版本卡片可 **置顶** 并设置 **P1 / P2 / P3 优先级**；排序时置顶版本优先，其余按 P1 → P2 → P3 排列，未设置优先级的版本排在后面。工作台的待发版版本也遵循同一优先级顺序。
- 可手动 **关闭发版** / **重新开启**，关闭后不再计入工作台待发版版本。
- 测试时间、置顶、优先级与关闭状态只保存在本机 `data/app-data.json`，不写回禅道，也不依赖禅道同步；清空两个时间即可取消排期，若仍保留置顶或优先级，卡片会继续显示。
- 工作台顶部「发版：…」与待发版数量使用同一口径：只展示和统计已经设置测试结束时间、且尚未结束的版本；只设置开始时间的版本和测试结束时间已过的版本都不会出现在顶部。未排期版本不出现在发版队列中。
- 「从禅道刷新版本」复用后台全量同步，不额外调用禅道构建或发布接口。

### 任务管理

- 自动汇总账号可访问项目下的全部任务。
- 范围：我的任务 / 测试任务 / 全部任务。
- 项目数量条与项目下拉筛选，按项目归类。
- 支持关键词、优先级、项目、今日到期筛选。
- 任务详情展示执行、截止日期、工时、说明与变更记录。
- 点击「新建任务」可手动创建本地任务，填写标题、内容、开始时间、结束时间、优先级，并可选择置顶。
- 本地任务保存在 `data/app-data.json`，参与任务看板 / 列表、时间筛选和工作台统计，但不会写入禅道；支持编辑、标记完成、重新打开、删除和置顶切换。
- 任务管理页的状态流转只作用于本地任务；禅道中的已有任务仍然只读。
- 可通过技能脚本在本地创建任务：`node scripts/add-task.mjs --title "回归验证" --priority P1 --pinned`。

### Bug 跟踪

- Bug 范围：我提交的 / 指派给我 / 客服反馈 / 全部（账号相关并集）。
- 「客服反馈」中的 Bug 带有「AI客服」来源标记，标题下方展示禅道优先级。
- 按产品归类，展示每个产品的 Bug 总量、未关闭量、P0/P1 未关闭数、我提交数与指派给我数。
- 默认按更新时间从新到旧；创建时间、更新时间均支持升序 / 降序。
- 同时展示创建时间与更新时间，移动端自动切换为卡片。
- 支持关键词、严重程度、状态（含「未关闭」聚合项）、产品、版本与类型筛选；顶部版本下拉可直接选择任意版本，并显示当前范围内的 Bug 数量。
- 点击 Bug 标题进入独立整页详情（不是弹窗）：左侧为 Markdown / HTML 渲染后的复现步骤、预期 / 实际结果、附件截图与处理记录，右侧为 Bug 属性，并保留禅道直达链接。
- 详情页顶部提供「上一个 / 下一个 Bug」按钮和当前列表位置，支持键盘 ← / → 快速切换；切换顺序与当前 Bug 列表的范围、筛选和排序保持一致。
- 复现步骤中的 Markdown 与禅道图片会自动渲染；图片经本地服务代理读取，不需要额外登录。
- 复现步骤、预期 / 实际结果中的 http(s) 链接会自动变为可点击链接，点击后在新窗口打开。
- 详情地址可直接分享或刷新，例如 `http://127.0.0.1:4173/#/bugs/11793`。
- 「登记 Bug」可选择账号可访问的产品，并填写严重程度、优先级、类型、指派账号、项目 / 执行、复现步骤等。

### Bug 编辑与状态流转（通过禅道 CLI 写入）

- 独立编辑页 `#/bugs/:id/edit`，与详情页一致保持整页布局。
- 可编辑标题、严重程度、优先级、类型、影响版本、所属项目、所属执行、相关需求、指派账号和复现步骤。
- 详情页与编辑页提供与禅道一致的操作：编辑、指派、解决、关闭、激活、删除；禅道 22.5 及以上额外提供「确认」。
- 解决时可选择解决方案、解决版本、指派人和备注；激活时可调整影响版本；关闭可填写备注。
- 所有写入都先经过本地参数校验，再调用 `zentao bug update / resolve / close / activate / confirm / delete`；成功后只重新读取该 Bug 并增量更新本地快照，不触发全量同步。单条读取失败时才回退到后台全量同步。
- 受禅道 22.4 CLI 接口限制，所属产品与所属模块不能在 QDesk 修改；需要时请到禅道调整。
- 删除是不可逆的正式操作，提交前会二次确认。

### 任务

- 已有任务只读，状态流转请到禅道完成。

### 工作日报

- 每个工作日自动生成当天日报草稿；任务、Bug、版本或 AI 客服数据变化后立即重新采集并自动保存，只有日报内容实际变化时才写入，手动保存或提交后不再自动覆盖。
- 日报模板：版本测试进度、今日新增 / 验收 / 按版本分别统计的剩余未关闭 Bug、今日任务及完成进度、AI客服今日新增 / 验证已关闭 / 指派开发。
- 版本测试进度只统计已设置发版测试时间的版本；只有一个版本时，剩余未关闭 Bug 取该版本的未关闭数量；多个版本时，每个版本行分别显示自己的剩余未关闭 Bug；没有排期版本时不显示全量剩余数。任务完成进度优先按禅道已消耗工时与剩余工时计算。
- 支持一键复制紧凑纯文本：版本测试进度、今日新增 / 验收 / 对应版本剩余未关闭 Bug、今日任务、AI客服今日新增 / 验证已关闭；复制内容不含标题、页脚和「指派开发」。
- 支持草稿、提交、转回草稿、重新采集。
- 支持导出 Markdown、导出任务 / Bug CSV。
- 日报保存在本地，不回写禅道。

### 偏好与数据

- 配置禅道连接（URL、账号、密码、显示姓名）。
- 展示产品数、项目数、自动同步计划、下次同步时间、最近同步时间、同步耗时和错误。
- 维护岗位、团队、迭代等展示信息。
- 本地任务与禅道任务统一参与任务导出；Bug 支持 JSON / CSV 导出。

## 同步机制

- 服务启动时读取 `data/snapshot-cache.json` 中的最近成功快照。
- `/api/bootstrap` 立即返回本地快照，页面打开不等待禅道 CLI。
- 工作日 **08:30–18:00**（本地时间）每 **30 分钟**自动执行一次全量同步；周末和每天 18:00 之后不自动同步，只有用户点击「立即同步」才触发全量同步。
- 首次安装没有本地快照时，会在后台执行一次初始化同步。
- 首次启动无快照时会返回结构完整的空快照，页面显示后台读取进度。
- 同步失败时保留旧快照，继续显示上一次数据，并记录脱敏错误。
- 右上角「禅道同步」只发起后台同步，接口立即返回 `202`。
- Bug 编辑、指派、解决、关闭、激活或删除后，只调用 `zentao bug <id>` 更新这一条记录、递增 `revision` 并写回本地快照；前端检测到 `revision` 变化后立即刷新，不启动全量同步。

一次完整同步会：

1. 读取全部可访问产品。
2. 读取全部项目与执行，并保留属于可访问项目的执行。
3. 对每个产品分别查询 `openedbyme` 与 `assignedtome` 的 Bug，按 ID 去重合并。
4. 并行扫描 `watch.autojobAccounts` 创建的 Bug（默认 `autojob`），筛选出指派给我、由我解决或由我关闭的记录；该扫描结果缓存 15 分钟。
5. 对每个执行查询任务。
6. 生成按产品分组的 Bug 统计、按项目分组的任务统计和客服反馈统计。

## 配置

`config.json` 可参考 `config.example.json`。常用字段：

| 字段 | 说明 |
| --- | --- |
| `server.host` / `server.port` | 本地监听地址与端口，默认 `127.0.0.1:4173` |
| `tester.account` | 当前禅道登录账号；使用 CLI Profile 时需填写 |
| `tester.name` | 显示姓名，可留空 |
| `zentao.cacheSeconds` | 快照新鲜度阈值，最小 60，默认 300；只用于展示 `stale`，不再触发自动同步 |
| `zentao.syncIntervalMinutes` | 工作日自动全量同步间隔（分钟），默认 `30`，使用本机时区；设为 `0` 时改用 `syncTimes` 固定时间点 |
| `zentao.syncWindow` | 自动同步时间窗，默认 `{ "start": "08:30", "end": "18:00" }`；窗口外不自动同步 |
| `zentao.syncWorkdays` | 自动同步的星期，默认 `[1, 2, 3, 4, 5]`（周一至周五）；`0` 为周日 |
| `zentao.syncTimes` | 旧版固定同步时间点，仅当 `syncIntervalMinutes` 为 `0` 时生效，默认 `["08:30", "12:00", "17:00"]` |
| `zentao.openedBuild` | 创建 Bug 时的影响版本，默认 `trunk` |
| `zentao.openedBuildLabel` | 影响版本显示名，默认「主干」 |
| `zentao.moduleNames` | 可选：模块 ID 到显示名的映射 |
| `zentao.bugModules` | 可选：登记 Bug 时可选的模块列表 |
| `zentao.cliPath` | 可选：自定义 `zentao.js` 路径 |
| `watch.enabled` | 是否启用客服反馈看板，默认 `true` |
| `watch.autojobAccounts` | AI 客服账号列表，默认 `["autojob"]` |
| `watch.productIds` | 可选：只扫描这些产品 ID；空数组表示全部可见产品 |
| `watch.label` / `watch.description` | 看板标题与来源说明 |

环境变量：

- `QDESK_PORT` / `QDESK_HOST`
- `ZENTAO_ACCOUNT`
- `ZENTAO_PRODUCT_ID`（仅作为创建 Bug 的默认产品回退）
- `ZENTAO_CLI_JS`
- `QDESK_AUTOJOB_ACCOUNTS`（逗号分隔，默认 `autojob`）
- `QDESK_AUTOJOB_PRODUCTS`（逗号分隔产品 ID，留空表示全部）
- `QDESK_SYNC_INTERVAL_MINUTES`（工作日同步间隔分钟，默认 `30`，设为 `0` 回退固定时间）
- `QDESK_SYNC_WINDOW`（同步时间窗，格式 `08:30-18:00`）
- `QDESK_SYNC_WORKDAYS`（逗号分隔的星期，默认 `1,2,3,4,5`）
- `QDESK_SYNC_TIMES`（旧版固定同步时间，仅当间隔为 `0` 时生效）

## Windows 开机自启

```powershell
powershell -ExecutionPolicy Bypass -File .\install-autostart.ps1
```

默认注册计划任务 `QDeskWorkbench`，在当前用户登录后通过 `start-hidden.vbs` 静默启动。服务已在运行时不会重复启动。

取消：

```powershell
powershell -ExecutionPolicy Bypass -File .\uninstall-autostart.ps1
```

如果修改了端口，请同步修改 `start-hidden.vbs` 中的 `healthUrl`，或使用技能安装器重新生成。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/health` | 服务、快照、后台同步状态和错误（已脱敏） |
| GET | `/api/connection` | 当前连接（不含密码） |
| POST | `/api/zentao/test` | 测试连接，返回可访问产品 / 项目数量 |
| POST | `/api/zentao/connection` | 保存连接并启动后台同步 |
| GET | `/api/zentao/file/:id` | 代理读取禅道图片 / 附件（仅图片格式，凭证不出本机） |
| GET | `/api/bootstrap` | 立即返回本地快照；`?meta=1` 返回同步状态；`?refresh=1` 触发后台刷新 |
| POST | `/api/sync` | 发起后台同步，返回 `202` |
| GET | `/api/bugs?scope=opened\|assigned\|autojob\|all` | Bug 列表与统计 |
| POST | `/api/bugs` | 创建正式 Bug |
| POST | `/api/bugs/:id/refresh` | 只读取并刷新这一条 Bug，不触发全量同步 |
| GET | `/api/tasks?scope=mine\|test\|all` | 任务列表与统计 |
| POST | `/api/tasks` | 创建本地任务（标题、内容、开始 / 结束时间、优先级、置顶） |
| PATCH | `/api/tasks/:id` | 更新本地任务、状态或置顶 |
| DELETE | `/api/tasks/:id` | 删除本地任务 |
| GET | `/api/releases` | 版本目录、测试窗口、置顶 / 优先级与已保存的 `releasePlans` |
| POST | `/api/releases` | 保存测试时间、置顶、优先级，并关闭 / 重新开启单个版本 |
| GET / POST | `/api/reports` | 日报读取与保存 |
| POST | `/api/settings` | 展示信息与界面偏好 |

## 数据存储

| 数据 | 位置 |
| --- | --- |
| 日报、本地任务、发版测试时间 / 置顶 / 优先级、展示信息、范围偏好 | `data/app-data.json` |
| 禅道连接（含本地密码） | `data/zentao-auth.json` |
| 最近成功快照（含任务 / Bug 业务数据） | `data/snapshot-cache.json` |
| 界面偏好 | 浏览器 `localStorage`，键名 `qdesk.ui.v2` |

`data/` 已加入 `.gitignore`。密码和快照均只保存在本机，静态资源接口不会暴露 `data/`。

## 安全与边界

- 服务默认只绑定 `127.0.0.1`。
- 密码只保存在本机 `data/zentao-auth.json`，接口只返回 `hasPassword`。
- 错误信息会替换密码后再返回，日志不记录请求体或凭证。
- 禅道已有任务只读；本地任务只保存在 QDesk，不产生禅道写入。已有 Bug 仅当 `assignedTo` 为当前账号时，才可通过禅道 CLI 编辑、指派、解决、关闭、激活和删除。
- 只有主动提交「登记 Bug」或 Bug 编辑 / 状态操作时才会向禅道写入记录；写入后只增量刷新该 Bug，不触发全量同步。
- 已启用静态资源白名单、CSP、`X-Frame-Options: DENY`、同源校验和请求体大小限制。
- 这是个人效率工具，不替代正式项目管理和缺陷管理系统。
